Configure screen: five ways to pick a backend

Quick Fix, branch ft/cursor-backend, 2026-10-20. Today's screen has one OpenAI key, a model dropdown and the tone-of-voice box.

What Raycast allows. A Form offers dropdown, text, password, checkbox, text area, description and separator fields. No tabs, no show/hide API. A field can change or disappear only by re-rendering from state (a dropdown's onChange sets state). Anything bigger than one form needs a List that pushes forms. Raycast also has a separate Extension Preferences screen declared in package.json.

The first field is the backend. The key label, hint text and model list follow it. Each backend keeps its own stored key and model, so switching never loses anything.

For
  • Closest to today's screen. Users see one key field.
  • Fits the Backend interface directly.
  • Adding a backend adds one dropdown item.
Against
  • Can't see at a glance whether the other backend has a key.
  • Unsaved edits to the hidden backend are easy to forget.

Configure becomes a List. Each backend is a row with its status. Enter opens a small form (key, model). An action sets the active backend. Tone of voice gets its own row.

For
  • Status of every backend at a glance.
  • Small forms, one job each. Scales to many backends.
  • Active backend changes without opening a form.
Against
  • More screens and more code than one form.
  • A bigger change to the layout users know.

Keys and the backend choice are declared as preferences in package.json. Raycast shows them in its own settings screen, with password fields. Configure keeps the model and tone.

For
  • Raycast's built-in, standard place for secrets.
  • Raycast handles the fields and stores the values.
Against
  • Settings split across two screens, which is confusing.
  • Preferences are static. The model list can't follow the backend there, so the model has to live in Configure.
  • Existing users' key in LocalStorage needs a migration.

A profile bundles backend, key, model and tone. We ship three fixed commands (fix-1, fix-2, fix-3) so each profile can have its own hotkey. Raycast can't add commands at runtime, hence the slots.

For
  • Pick backend and tone from the hotkey. Different style for Slack and email.
  • Natural place for per-model settings such as thinking off.
Against
  • Most code, most state, and a migration.
  • More than this change needs. Think of it as a later step.

Do we have a lot of options?

Not many, because Raycast's UI is limited. The real choice is between three shapes: one form (options 1, 2), a list that pushes forms (options 3, 5), or Raycast Preferences (option 4). I'd start with option 1. It keeps today's screen and adds a Backend dropdown on top. If a third backend or per-tone profiles show up, move to option 3.

Also needed in any option: a "Test connection" action on Configure, since Cursor can fail at the network layer (the Netskope HTTP/2 issue) and a clear message beats a silent 15 second wait.
